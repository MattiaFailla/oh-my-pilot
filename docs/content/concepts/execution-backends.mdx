# OMP Execution Runtime

oh-my-pilot executes every agent task through [Oh My Pi (OMP)](https://github.com/can1357/oh-my-pi). There are no selectable coding-agent backends and no direct model-provider API integration in oh-my-pilot.

<Callout type="info">
OMP owns authentication, provider selection, and model profiles. oh-my-pilot owns task orchestration, worktrees, quality gates, GitHub lifecycle operations, and observability.
</Callout>

## Requirements

- OMP `18.0.5`, available as `omp`
- An initialized OMP profile with your provider credentials
- Git; GitHub CLI (`gh`) when GitHub features are enabled

Check the runtime with:

```bash
omp --version
oh-my-pilot backend status
```

## Configuration

```yaml
executor:
  type: omp
  omp:
    command: omp
    version: "18.0.5"
    profile_dir: /home/pilot/.omp
```

`profile_dir` becomes `PI_CODING_AGENT_DIR` for every OMP process. Mount it read-only in containers. Do not put provider API keys in oh-my-pilot configuration or environment variables.

## RPC Integration

The executor starts OMP with `--mode rpc` and uses JSONL frames. It negotiates protocol v2 when offered, reassembles chunked payloads, streams assistant and tool events to the task timeline, and creates one process per task attempt.

OMP can request Pilot-owned host tools. The quality-gate tool executes under the runner's task context; GitHub publication stays runner-owned so agent processes cannot bypass branch, PR, and approval policy.

## Model and Effort Routing

By default, model selection stays in the OMP profile. Set `executor.model_routing` only when you intentionally want oh-my-pilot to pass explicit OMP model IDs for each complexity class. Effort routing maps Pilot's task complexity to OMP thinking levels.

## Migration

Replace legacy executor configuration with the OMP block above, remove any provider keys from deployment secrets, and delete old `.claude` project settings. Project instructions generated by `oh-my-pilot init --project` now use `AGENTS.md`.
